# 手机端 MoE：Flash→DRAM 预取与专家激活剪枝协同设计

日期：2026-09-18。目标平台：手机；存储层级：Flash–DRAM–SRAM；请求 batch size 固定为 1。

本文聚焦 **Flash→DRAM 专家权重加载**，以单请求逐 token decode 为主要优化阶段。所有算法均为待实现、待实验验证的提案。文献背景见[MoE 预取调研](D:/华为/MoE-Compressors/docs/research/moe_prefetch_survey_2026-09-18.md)。

## 1. 目标与设计范围

核心问题是：

> 在模型质量和手机可用 DRAM 预算内，尽早识别实际需要的专家，减少 Flash 读取，并把仍然必要的读取尽量隐藏在单请求的计算过程中。

采用三项协同机制：

| 机制 | 决策 | 主要收益 |
|---|---|---|
| A. 质量约束的冷专家跳过 | 哪些缺失专家值得从 Flash 读入 | 避免不必要的读取和关键路径等待 |
| B. 剪枝后需求预取 | 提前读谁、提前多远、读多少 | 隐藏必要读取，减少读取后又被跳过的浪费 |
| C. DRAM 内替换补偿与保留 | 哪些已驻留专家可复用，哪些值得留到后续 token | 在质量允许时覆盖冷专家需求，降低重复读取 |

A+B 是第一阶段主方案；C 在已有替换质量校准的基础上作为增强项。各层激活阈值、预取深度和缓存配额作为少量可调参数，通过离线 profiling 和验证选取。

### 1.1 固定的执行条件

- 单请求、batch=1；decode 每一步处理一个新 token，利用相邻层计算和历史 token 信息创造预取机会。
- 完整量化专家权重保存在 Flash，DRAM 只缓存部分专家；量化格式在主实验中固定。
- SRAM 用于计算后端的片上数据复用。DRAM 中有专家不代表 SRAM 命中，相关读取和 kernel 时间仍计入计算成本。
- attention、router、embedding、KV cache、预测器及补偿参数采用明确的内存策略，计入手机整体 DRAM 预算。
- 单请求 prefill 仍可有多个 prompt token。它与 batch=1 并不矛盾；其 TTFT、Flash 读取和给 decode 留下的缓存状态单独评估。
- CPU/GPU/NPU 的实际执行后端由设备能力决定；选择哪一种计算单元都不能消除冷权重的 Flash 读取依赖。

本设计的算法控制对象是 Flash 读取与 DRAM 专家缓存。后端额外复制、反量化和 SRAM 数据搬运通过实测成本计入时间线。

### 1.2 与已有研究的关系

[AdapMoE](https://arxiv.org/abs/2408.10284) 已结合动态 gating、预取与缓存；[SpecPrefetch](https://arxiv.org/html/2607.24787v2) 的低秩预测和预算限制适合借鉴；[HOBBIT](https://arxiv.org/abs/2411.01433) 包含存储受限端侧实验。

[BuddyMoE](https://arxiv.org/abs/2511.10054)、[APEX](https://arxiv.org/abs/2608.11688)、[SPICE](https://arxiv.org/abs/2608.21240) 是替换/近似的比较对象；[SeqMoE](https://arxiv.org/abs/2609.12978) 提供序列预测和截止时间调度思路。其不同存储层级上的速度数字不直接作为手机 Flash 加载收益。

研究增量需要由“同质量、同 DRAM 预算、同手机实际 Flash 路径”的比较证明。

## 2. Flash 读取与 DRAM 缓存模型

### 2.1 按真实可用性划分状态

| 状态 | 含义 | 对决策的影响 |
|---|---|---|
| ready | 权重已在 DRAM，格式和同步条件允许执行 | 本次使用不需要 Flash 读 |
| preparing | 数据已进入 DRAM，仍需解码、布局转换或后端准备 | 还有准备等待，不能算作冷 Flash miss |
| inflight | 存储读取已提交，尚未完成 | 评估剩余完成时间；已发生的读取不可追回 |
| queued | 应用层计划读取，但尚未提交 | 可改优先级或取消，最容易真正省掉读取 |
| cold | 当前没有可复用的 DRAM 副本 | 必须读入，或在质量允许时跳过/替换 |

状态以专家及其所需块为单位；一个专家的部分数据已到位，不代表完整专家可执行。初版以完整专家可用后执行为语义，不依赖细粒度计算流式化。

**page cache 也是 DRAM。** 应用缓存 miss、文件 read、实际存储读取是三个不同事件。mmap 只建立映射，未必把权重读入 DRAM；内核 readahead 则可能读取应用未显式请求的页。若权重已在 page cache，不能把它按冷 Flash 读取计费。

### 2.2 内存约束

以设备允许本任务使用的 DRAM 预算为上限：

    M_fixed + M_KV(t) + M_expert_cache + M_IO_buffers
            + M_predictor + M_compensation + M_workspace ≤ M_budget

同时为系统运行与内存波动留余量。这里统计物理上不同的占用：共享映射不重复计数；page cache 与应用另行复制的权重若并存，则两份都计入。预测器、补偿表和量化元数据不能占用未记账的额外内存。

KV cache 随上下文增长会压缩可供专家使用的空间；测试需覆盖不同上下文长度，并在内存压力下缩减缓存/预取预算。

以完整专家执行为初版语义，预算须至少支持一个专家及必要工作区的峰值。提交预取时为 demand 读入与执行保留空间，避免全部槽位被推测 inflight 请求占满；活动缓冲区释放后再推进后续读取。

### 2.3 完成时间与可隐藏窗口

用设备 profiling 估计一个冷专家的就绪时间：

    A_e − now ≈ 应用/存储排队
                + 请求服务固定开销
                + 剩余有效读取字节 / B_eff
                + 格式准备时间

B_eff 依赖请求大小、连续性、队列深度、并发系统 I/O 和设备状态，不使用 UFS 标称顺序带宽代替。对 inflight 请求优先使用其状态对应的剩余完成时间分布，必要时使用保守分位数。

    W = 目标层预计用到专家的时刻 − 当前可发起读取的时刻
    局部剩余等待 ≈ max(0, A_e − 目标使用时刻)

多个读取共享 Flash 队列和 DRAM 空间，端到端等待不能简单按专家相加。调度模型须包含实际计算、I/O 重叠和队列竞争。

**预取窗口是否足够是实测问题。** 同层 attention 时间可能短于一个专家的 Flash 读取时间；此时可以跨更多层提前预测，或只预取最有价值的部分候选。加深 lookahead 也会增加预测误差和缓存占用。

### 2.4 剪枝节省必须分账

对最终跳过的专家：

- 读取尚未提交：可减少本次新增读取；若与其他必需数据共用读取块，按实际可省块数计。
- 已在读取：最多取消尚未提交部分或受接口支持的请求；实际已读字节仍计入。
- 已经 ready：主要节省计算及 DRAM→SRAM 流量，不再节省刚才的 Flash 读取。
- 被跳过但有高后续复用价值：是否保留已到位数据交由缓存策略决定，避免反复读入。

因此，**晚期剪枝可降低当前等待，早期剪枝需求预测才有机会系统性减少 Flash 流量。** 两者都必须测量。

## 3. 机制 A：质量约束的冷专家跳过

### 3.1 决策目标

真实 router 对 token t、层 l 给出集合 R 和权重 w，运行时提供状态 z。选择最终保留集合 S：

    S* = argmin(S∈候选集) T̂_layer(S, z)
    约束：D̂_upper(S | x, w, l) ≤ ε_l
          |S| ≥ k_min
          可选：保留原 top-1

T̂_layer 包括必要 Flash 读取、队列、准备和专家计算；D̂_upper 是经过独立验证校准的保守质量风险估计。质量相近且预计时间接近时，可优先选择新增 Flash 字节更少的候选。

原始 R 始终作为精确执行 fallback；其实现可逐专家读取和执行，不要求所有原生 top-k 权重同时放进 DRAM。

### 3.2 质量模型与候选

离线采集原模型输出及少量 skipping mask 的输出，拟合：

    D_l(S) = ||y_original − y_S||² / (||y_original||² + η)

结合层敏感度、路由权重/熵、被删概率质量和专家条件误差。线上只使用这些廉价特征，不能先读入并计算待跳过专家的完整输出再判断。

重归一化、多个专家同时删除和补偿会产生非加性误差，应校准最终聚合输出；局部误差阈值仍需通过全模型任务质量评测验证。

初版只检查少量候选：

1. 原始 R；
2. 几个经过校准的 top-p / top-k 前缀；
3. 在这些候选中，对会造成较大等待的冷专家做一到两次质量可行的移除；
4. 机制 C 提供的少量已驻留替换候选。

优先保留质量重要、已就绪或很快就绪的专家，但 ready 状态不是无限扩展激活数的理由：它们仍占用计算和 DRAM 带宽。

### 3.3 关键路径收益

对删除候选 e，比较：

    ΔT_e = T̂_layer(S, z) − T̂_layer(S \ {e}, z)

这不是 e 的孤立 Flash 读取时长。一个 miss 若可完全隐藏在其他计算里，删除它可能不降低本层完成时间；一个权重低、真正拖住本层结束的冷专家，则更值得在质量预算内跳过。

选择之后优先执行 ready 专家，同时读取剩余必需专家；先完成质量决策，再按固定规则聚合，避免异步到位顺序改变数值语义。

## 4. 机制 B：剪枝后需求预测与 Flash 读取调度

### 4.1 提前预测什么

使用当前层较早的 hidden state、历史路由及当前缓存状态，预测未来层的实际保留需求：

    q_e = P(e 在目标层最终需要执行 | 当前可因果获得的信息)

第一阶段固定一个质量合格的 skipping 策略，采集它实际运行后的轨迹训练轻量预测器。基线使用提前运行原生 gate；训练式方案使用小型低秩映射或 MLP，计入所有层的总参数量与推理成本。

到位感知 skipping 使标签依赖调度状态，因此采用离线迭代：冻结策略采集轨迹 → 训练 predictor → 回放/运行得到到位模式 → 重新校准 skipping。不能使用未来真实路由或真实未来缓存作为线上输入。

### 4.2 预测窗口

以**同一 token 跨层提前预测**为主。profiling 比较少量 lookahead 配置，选择质量、读完概率和 DRAM 占用合适的窗口。

首个 MoE 层的初次调用按冷启动必要读取处理；后续 decode step 可以利用上一 token 的表示/路由历史预测首层需求，但它仍是有误差的预测。跨 token 预取只在命中收益覆盖额外 DRAM 驻留和错误读取时启用。

增加深度不能无条件填满读取队列。高置信度、难以替代且读取代价大的专家优先获得窗口。

### 4.3 限额与优先级

先识别 ready、preparing 和已有 inflight/queued 请求，合并重复需求并更新使用时刻与优先级，不重复发起读取。对新增的可选预取估计：

    V_e = E[本次提前读取可减少的暴露等待 | 当前信息]
          − λ × 新增存储读取字节
          − μ × DRAM 占用代价

这是调度启发式，不是独立可加的最优价值。提交前检查共享队列和内存可行性。晚到的预取若仍比按需读取更早完成，也可能有部分价值；不把“无法完全赶上截止时间”简单等同于零收益。

预算包含：

- 可用于预取的 DRAM 字节；
- 未完成的预取读取字节；
- 并发读取请求上限；
- 由实测完成时间决定的有效 lookahead。

真实 router 确定的必要冷专家属于 demand，优先于可选推测请求；即使无法按时到位，也必须执行必要读取作为质量 fallback。

### 4.4 Flash 专用的读请求组织

- 固定量化格式，保存专家 ID→文件偏移、长度、元数据的索引；尽量让同一专家的数据形成较少的连续、对齐区间。
- 以专家为逻辑预取对象，以文件块/连续区间为物理读取对象；实际读取放大和合并时夹带的字节计入成本。
- 只有实测收益明确时才合并邻近候选，避免为了顺序性额外读入大量低价值专家。
- 对大请求可评估分块，权衡启动开销与需求响应；不假定更细粒度一定更快。
- 在应用层排队，限制提交到存储设备的推测请求深度，为新出现的 demand 留响应空间。
- 已提交存储请求的取消/抢占能力由平台决定；机制不得依赖即时抢占。每次计入实际已完成的字节与时间。

具体异步文件 I/O 接口按手机操作系统和权限选择。mmap、显式读取和可用的直接 I/O 有不同缓存语义，应固定一种基线路径再做比较。

## 5. 机制 C：DRAM 内的有向替换补偿与缓存保留

### 5.1 替换决策

复用仓库的 Q(i ← j)：在路由到 j 的 token 上，衡量 i 对 j 的条件可替代性。

当 j 是冷专家时，只从同层已经 ready 的专家中寻找初版替代候选。优先复用本 token 已经需要计算的 i：

    f_j(x) ≈ A_(i←j) f_i(x) + b_(i←j)

A 先限制为标量或对角缩放。比较“加载 j”“跳过 j”“复用 i 补偿 j”“额外计算已驻留 i”几个动作，在统一质量约束下选预计完成最快者。

额外执行驻留专家仍有计算和 DRAM→SRAM 成本。如果替代专家也要从 Flash 读取，其收益就需要重新比较，不能计为缓存内补偿。

### 5.2 校准与内存成本

- 用真实或模拟的 DRAM 缺失模式校准最终聚合误差和缩放；原 top-p 分布上的缩放参数不能自动适用于状态相关 mask。
- 多个冷专家映射到同一个替代专家时，评估相关误差与多样性损失。
- 只保存每个专家少量有支持数据的替换对，计入补偿表、索引和参数的 DRAM 占用。
- 对长尾、低样本和分布外情况使用保守 fallback。
- 本仓库的 Qwen3-MoE 路径不依赖原生 shared expert；替代基底来自已驻留的同层 routed expert。

### 5.3 缓存保留

第一阶段采用全局 DRAM 字节预算和 LRU 基线，缓存键包含层号和专家 ID，保护正在读取/准备/计算的缓冲区。

增强策略按短期价值保留：

- 后续 token 再次精确使用的可能性；
- 重读该专家的实测 Flash 代价；
- 对同层冷专家需求的、经质量校准的替代覆盖；
- 专家大小及预计占用时长。

缓存覆盖增益需按当前保留集合算边际值，防止留下一批覆盖高度重复的专家。不能仅用替换能力挤掉不可替代的长尾专家，也不为高热度专家放宽质量约束。

## 6. 统一执行流程与参数选择

    早期表示/路由历史可用：
        预测后续层的剪枝后需求
        去重并估计读取收益
        在 DRAM、字节和请求数预算内提交 Flash 预取

    当前层真实 router 可用：
        读取原始 top-k、权重和一致的 ready/inflight/queued 状态
        选择满足质量约束的保留与补偿计划
        取消失去用途的应用层排队请求
        提升必需冷专家读取优先级
        执行 ready 专家，与必要读取重叠
        等待、准备并执行仍然必要的专家
        按固定规则聚合，释放使用锁，更新缓存保留价值

各层使用少量经过验证的参数组合：

    θ_l = (激活/质量阈值, 预取深度, 预取字节预算)
    全局参数 = (专家缓存字节预算, 并发读上限, 块大小)

先 profiling，再用少量配置的事件回放与真实手机测试选择；不把独立层收益简单相加视作全局最优。剪枝缩短计算也会缩短后续读窗口，节省的计算可能被等待抵消，必须检查完整 token 时间线。

当温度、背景 I/O 或 KV 占用变化时，优先调节预取和缓存预算；质量相关阈值仅在已验证配置中切换。

## 8. 实验设计：手机、batch=1、实际 Flash 路径

### 8.1 基线与增量

| 组别 | 激活策略 | Flash 读取/DRAM 策略 | 要回答的问题 |
|---|---|---|---|
| B0 | 原始 top-k | 按需读 + LRU | 原始加载与等待有多少 |
| B1 | 原始 top-k | 预取 + 同一缓存 | 必要读取有多少可隐藏 |
| B2 | top-p / 层阈值 | 按需读 + 同一缓存 | 剪枝能减少多少冷读取 |
| B3 | 同 B2 | 剪枝后需求预取 | 已考虑剪枝的预取基线 |
| A+B | 到位/读取代价感知选择 | 同预测器、同资源预算 | 运行状态能带来多少额外收益 |
| A+B+C | 加 DRAM 内校准补偿 | 计入补偿的同总 DRAM 预算 | 可替代性是否进一步减少冷读取 |
| 缓存增强 | 同上 | 加短期使用/替代覆盖保留 | 是否减少跨 token 重读 |

用 AdapMoE 风格的质量门控、SpecPrefetch 风格的轻量预测和预算，以及 BuddyMoE 风格的替换作机制对照。实现若经过手机适配，明确是机制重实现，保持后端 kernel、量化与内存口径一致。

### 8.2 自变量

所有实验固定 batch=1，变化：

- 手机实际专家可用 DRAM 预算；
- 固定量化格式下的激活/质量阈值；
- lookahead、预取字节数、请求并发和块大小；
- 上下文长度、输出长度、不同任务；
- 请求内冷/热缓存、跨请求保留策略；
- 持续运行温度、系统背景读取等设备状态。

prefill 单独报告 TTFT 和 Flash 字节，记录结束时专家缓存；decode 明确从哪种缓存状态起测，避免隐藏预先读取全部权重的准备成本。

### 8.3 核心指标

1. **decode TPOT 均值、p50、p95，以及输出 tokens/s。**
2. **每 token 暴露的 Flash 等待**，与原始 I/O 时长、格式准备、计算分别记录。
3. **每 token 实际存储读取字节和请求数**；同时记录逻辑请求、page-cache 命中及应用缓存命中。
4. 错误预取、最终被剪掉的已读字节、取消前已读字节、被驱逐后重读字节。
5. 读取完成/ready 的时刻、必要专家按时就绪率、读取服务时间分布。
6. 总 DRAM 峰值、专家缓存、I/O buffer、KV、预测器与补偿的占用。
7. 任务准确率、PPL、长生成质量及分布外表现。
8. 可测时补充设备能耗、功耗和持续运行性能。

逻辑 read 返回的字节不能直接当作 Flash 实际读取字节。优先用平台可用的存储/缺页统计交叉核对；若只能得到应用层指标，明确标为估计，不能宣称精确测得 NAND 物理流量。内核 readahead、缓存副本和系统背景 I/O 都需说明口径。

### 8.4 公平性与验证

主要结论来自同手机、同模型/量化、同质量、同总 DRAM 和同缓存起点的比较。平均激活 k、命中率和 recall 仅作解释指标。

同时运行固定 token 序列的配对分析和自由生成评测；每个策略都执行自身的 hidden-state 路径。先在离线质量可行候选上估计潜力，再检查轻量线上策略能恢复多少收益。

关键消融：

- 只看 router 权重 vs 加层敏感度 vs 加冷读取完成时间；
- 晚期剪枝 vs 剪枝后需求提前预测，分开比较字节和等待；
- 应用缓存 miss vs 正确识别 page-cache/ready 状态；
- 仅 skipping vs DRAM 内替换/补偿；
- 相同平均 k vs 相同任务质量；
- 给定预取窗口的离线理想预测参照 vs 实际因果预测；
- 事件模拟 vs 手机真实存储路径。

未来已知的离线参照仍受 Flash 读取时间和 DRAM 容量约束，不能设为瞬时到位。模拟延迟注入可用于敏感性分析，手机收益结论由真实存储实验支持。

## 9. 推荐落地顺序

1. **建立可信的 Flash→DRAM 基线。** 固定存储格式和计算后端，测真实服务时间、缓存来源、字节和内存；确认显式读入的专家能被后端使用。
2. **实现 A+B 的最小闭环。** 先固定质量门控和轻量预测器，再加入真实到位/读取代价；同时检查是否减少字节、是否减少等待。
3. **加入 C 的 DRAM 内替换补偿。** 从少量高可信替换对开始，重新校准质量，计入参数与额外计算。
4. **调节少量层级参数和缓存保留。** 按完整单 token 时间线验证，最后覆盖长上下文与持续运行。

最终验收问题：

> 在手机 batch=1 推理、相同质量和总 DRAM 预算下，联合策略每个输出 token 少读了多少 Flash、少等了多久，并兑现为多少 TPOT 改善？

如果可接受质量下的冷专家大多不可跳过/替换，重点应转向必要读取的预测与复用；如果读取几乎已被隐藏，则 TPOT 的进一步改善需更多关注计算，减少 Flash 流量仍可作为资源和能耗目标。两种情况都以实测分解决定算法价值。
